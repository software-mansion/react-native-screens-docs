#### ios.bottomAccessory {#host-ios-bottomaccessory}
</ReferenceHeading>

```ts
bottomAccessory?: TabsBottomAccessoryComponentFactory;
```

Specifies component used as bottom accessory.

This prop is a function that accepts `environment` as a parameter and
returns the component that will be rendered in the bottom accessory.

If this prop is `undefined`, the bottom accessory will not be rendered.

In order to allow accessory rendering based on environment, the component
is rendered 2 times for both `'regular'` and `'inline'` environments at the
same time. Environment determines which component is visible at given
moment. This might require implementing a solution to share state between
both rendered components (e.g. usage of context).

**Type:** [`TabsBottomAccessoryComponentFactory`](#tabsbottomaccessorycomponentfactory)

#### ios.prominentScreenKey {#host-ios-prominentscreenkey}
</ReferenceHeading>

```ts
prominentScreenKey?: string;
```

`screenKey` of the tab screen that should receive the prominent treatment.

Must match the `screenKey` of one of the child `Tabs.Screen`s. Where
supported, that tab receives enhanced visual emphasis in the tab bar - it
is detached from the other items onto its own surface and stays visible
when the tab bar minimizes on scroll (see `tabBarMinimizeBehavior`).

When omitted, a tab with `role: 'search'` and
`automaticallyActivatesSearch` enabled becomes prominent automatically,
otherwise no tab is prominent.

**See:** [UITabBarController.prominentTabIdentifier](https://developer.apple.com/documentation/uikit/uitabbarcontroller/prominenttabidentifier)

#### ios.tabBarHiddenAnimationEnabled {#host-ios-tabbarhiddenanimationenabled}
</ReferenceHeading>

```ts
tabBarHiddenAnimationEnabled?: boolean;
```

Whether changes of `tabBarHidden` are animated.

When `true`, the tab bar is hidden and shown with the system transition.
When `false`, the tab bar disappears and reappears immediately.

On versions earlier than iOS 18 the tab bar visibility is never animated,
regardless of this prop.

**Default:** `true`

**See:** [UITabBarController.setTabBarHidden(\_:animated:)](https://developer.apple.com/documentation/uikit/uitabbarcontroller/settabbarhidden(_:animated:))

#### ios.tabBarSidebarPreferredPlacement {#host-ios-tabbarsidebarpreferredplacement}
</ReferenceHeading>

```ts
tabBarSidebarPreferredPlacement?: TabBarSidebarPreferredPlacement;
```

Specifies whether the sidebar or the tab bar is preferred when only one of
them can be displayed.

This prop requires `tabBarControllerMode` to be set to `'tabSidebar'`.
Otherwise, the sidebar is not considered a supported mode and the tab bar
is always displayed.

The button that shows the sidebar is visible only when the screen has a
header. After using it, the sidebar is displayed and the content is
accessible.

The sidebar can also be shown with a swipe from the leading edge. In this
case, the sidebar overlaps the content, and the content is not accessible
until the sidebar is hidden.

The sidebar is enabled only when the interface has a regular horizontal
size class. On iPhone, this applies only to larger models (e.g. Pro Max,
Plus and Air) in landscape orientation. On other iPhones (e.g. iPhone 18
Pro), and on all iPhones in portrait orientation, the tab bar is always
displayed.

**Type:** [`TabBarSidebarPreferredPlacement`](#tabbarsidebarpreferredplacement)

**Default:** `'automatic'`
