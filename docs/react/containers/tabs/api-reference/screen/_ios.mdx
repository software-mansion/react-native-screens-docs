#### ios.automaticallyActivatesSearch {#screen-ios-automaticallyactivatessearch}
</ReferenceHeading>

```ts
automaticallyActivatesSearch?: boolean;
```

Specifies whether selecting this tab automatically activates its search
field.

Effective only for tab screens with `role: 'search'` and only when a search
bar is configured in the header of the screen stack nested in this tab
(see `headerSearchBarOptions`). When enabled, selecting the search tab
immediately activates the search field. Cancelling the search restores the
previously selected tab.

**Default:** `false`

**See:** [UISearchTab.automaticallyActivatesSearch](https://developer.apple.com/documentation/uikit/uisearchtab/automaticallyactivatessearch)

#### ios.overrideScrollViewContentInsetAdjustmentBehavior {#screen-ios-overridescrollviewcontentinsetadjustmentbehavior}
</ReferenceHeading>

```ts
overrideScrollViewContentInsetAdjustmentBehavior?: boolean;
```

Specifies if `contentInsetAdjustmentBehavior` of first ScrollView
in first descendant chain from tab screen should be overridden back from
`'never'` to `'automatic'`.

By default, `react-native`'s ScrollView has
`contentInsetAdjustmentBehavior` set to `'never'` instead of UIKit-default
(which is `'automatic'`). This prevents ScrollViews from respecting
navigation bar insets.
When this prop is set to `true`, `'automatic'` behavior is reverted.

Supported only on Fabric.

**Default:** `true`

#### ios.role {#screen-ios-role}
</ReferenceHeading>

```ts
role?: "search";
```

Gives this tab a system role.

A tab screen with `role: 'search'` is backed natively by `UISearchTab`
(tabs are managed through the `UITab` API), which enables the system
search behavior: `automaticallyActivatesSearch` and the detached trailing
placement UIKit gives search tabs. Behavior differs between OS versions:
iOS 26.x detaches `UISearchTab` unconditionally, iOS 27.0 only while
`automaticallyActivatesSearch` is enabled. This prop does not affect the
tab bar item's icon or title - combine it with `systemItem: 'search'` for
the system magnifier item. On iOS 27+ the detached (prominent) placement
can be given to any tab instead through `Tabs.Host`
[ios.prominentScreenKey](#host-ios-prominentscreenkey).

The native tab class cannot change during the screen's lifetime - changing
`role` on a mounted tab screen is not supported and triggers an assertion
in development builds.

**See:** [UISearchTab](https://developer.apple.com/documentation/uikit/uisearchtab)

#### ios.scrollEdgeAppearance {#screen-ios-scrolledgeappearance}

```ts
scrollEdgeAppearance?: TabsScreenAppearanceIOS;
```

Specifies the tab bar appearance when edge of scrollable content aligns
with the edge of the tab bar.

Allows to customize the appearance depending on the tab bar item layout
(stacked, inline, compact inline) and state (normal, selected, focused,
disabled).

If this property is `undefined`, UIKit uses `standardAppearance`, modified
to have a transparent background.

**Type:** [`TabsScreenAppearanceIOS`](#tabsscreenappearanceios)

#### ios.selectedIcon {#screen-ios-selectedicon}
</ReferenceHeading>

```ts
selectedIcon?: TabsScreenIconIOS;
```

Specifies the icon for tab bar item when it is selected.

Supports the same values as `icon` property. It must use the same icon
`type` as `icon`; `renderingMode` may differ.

To use `selectedIcon`, `icon` must also be provided.

**Type:** [`TabsScreenIconIOS`](#tabsscreeniconios)

**Example:** Different rendering modes

The symbol is tinted while unselected and shows its own colors while
selected.
```tsx
<Tabs.Screen
  screenKey="home"
  ios={{
    icon: { type: 'sfSymbol', name: 'star' },
    selectedIcon: {
      type: 'sfSymbol',
      name: 'star',
      renderingMode: 'original',
    },
  }}
/>
```

#### ios.systemItem {#screen-ios-systemitem}
</ReferenceHeading>

```ts
systemItem?: TabsScreenSystemItem;
```

System-provided tab bar item with predefined icon and title

Uses Apple's built-in tab bar items (e.g., bookmarks, contacts, downloads)
with standard iOS styling and localized titles. Custom `icon` or
`selectedIcon` properties will override the system icon, and the
system-defined title can be overridden by providing a custom `title`.

On iOS 26, `systemItem: 'search'` acts as a detached tab bar item, which
does not display any title (system or custom). This no longer applies on
iOS 27; to get a similar separation use `role: 'search'` together with
`automaticallyActivatesSearch`.

**Type:** [`TabsScreenSystemItem`](#tabsscreensystemitem)
